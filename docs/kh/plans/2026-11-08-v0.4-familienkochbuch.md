# Familienkochbuch v0.4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A book editor with live preview turns a Mealie cookbook (or a single recipe) into a printable PDF via the print dialog. The release also gets an "own photo" flag, a duplicate report for moving from other apps, and a fan-oven bracket in the step text.

**Architecture:**
- Backend `mealie/kh/books/` holds the cookbook print settings and the recipe flags. Backend `mealie/kh/duplicates/` holds the household-wide duplicate report and reuses `mealie/kh/drafts/duplicates.py`. One additive migration `kh0004` adds three tables.
- The frontend lives in our layer:
  - pure logic in `lib/oven.ts` and `lib/book.ts`;
  - a print component `KhPrintBook` that is both the preview and the printout;
  - the editor `KhBookEditor` and three pages.

**Tech Stack:** FastAPI, SQLAlchemy and Alembic (`kh` branch), Pydantic; Nuxt 4, Vue 3, Vuetify; pytest, Vitest; CSS `@media print`.

**Spec:** `docs/kh/specs/2026-11-08-familienkochbuch-design.md` (D43)

**Start:** after `v0.3` is merged into `main`, on a new branch `kh/v0.4-kochbuch` in its own worktree. Task 4 builds on `frontend/kh/app/lib/step-text.ts` from `v0.3`.

## Global Constraints

- No new dependency (Python or npm); PDF only through the browser's print dialog. (Spec F1, Nicht-Ziele)
- Migrations only add tables; `kh0004` revises `kh0003`. (CLAUDE.md, Fork-Regeln)
- Our code in `mealie/kh/`, `frontend/kh/`, `tests/kh/`. Mealie files change minimally and carry `KH: <reason>`. Never edit `frontend/app/lib/api/types/` or Mealie's locale files. Our TS API types are written by hand, as in `frontend/kh/app/lib/api/notices.ts`.
- New texts only in `frontend/kh/lang/de-DE.json` and `en-US.json`, under `kh.book.*`, `kh.duplicates.*` and `kh.oven.*`.
- Named constants:
  - `OVEN_FAN_DIFFERENCE = 20` °C;
  - `OVEN_MIN_TEMPERATURE = 100` °C;
  - `DUPLICATE_REPORT_LIMIT = 200`;
  - `BOOK_AUTOSAVE_MS = 1000`;
  - page margin 15 mm.
- Photos in any printout only for recipes with `own_photo = true`. The server enforces this; the editor only reflects it. (Spec F4)
- Test data self-written, no foreign recipes or photos. Tests never call real AI (D23).
- Test commands (from `.claude/CLAUDE.md`):
  - Backend: the docker pytest command. For a part, append the path, e.g. `pytest tests/kh/books`.
  - Frontend: the docker vitest command. For one file, use `pnpm vitest run kh/app/__tests__/<file>`.
  - Both whole suites, `ruff format --check`, `ruff check mealie` and `pnpm lint --max-warnings=0` must be green before every commit.

## Review Focus

1. A cookbook whose filter finds 0 recipes: the hint text from the spec shows, no empty title page prints, and saving still works. → test in Task 5 (`book.ts`) and by hand in Task 7.
2. A recipe removed from the cookbook, or deleted, still sits in the saved settings: it is ignored and does not break the book. Re-added later, it starts with the defaults. → test in Task 5.
3. A user of another household opens the book editor of a cookbook they may read: they see it and can print, and saving returns 403 with a readable message, not a silent failure. → test in Task 2, UI handling in Task 7.
4. Someone asks for photos for a recipe without the own-photo flag through the API: the stored settings come back with the photo off. → test in Task 2.
5. Temperatures that are not oven temperatures, such as "auf 60 °C abkühlen", "Kerntemperatur 75 °C" or "−18 °C": no bracket. → test in Task 4.

### Task 2: Book settings and recipe flags API

**Files:**
- Create: `mealie/kh/books/schemas.py`, `mealie/kh/books/service.py`, `mealie/kh/books/routes.py`
- Modify: `mealie/kh/routes.py` (include the router, tag `"KH: Books"`)
- Test: `tests/kh/books/test_kh_books_routes.py`

**Interfaces:**
- Consumes: the models from Task 1.
- Produces:
  - `BookRecipeSettings(include: bool = True, photo: bool = False, servings: float | None = None)` (`servings` > 0 or None).
  - `BookSettings(title: str | None = None, subtitle: str | None = None, title_page: bool = True, toc: bool = True, order: Literal["category", "alpha"] = "category", description: bool = True, notes: bool = True, oven: bool = True, recipes: dict[str, BookRecipeSettings] = {})`. Keys of `recipes` are recipe slugs. Strings are at most 120 characters. Camel-case aliases follow Mealie's schema style.
  - `GET /api/kh/cookbooks/{cookbook_id}/print` → `BookSettings`: the stored settings or the defaults. Readable by anyone in the group who can read the cookbook (Mealie lets other households read cookbooks).
  - `PUT /api/kh/cookbooks/{cookbook_id}/print` (body `BookSettings`) → `BookSettings` as stored.
    - Only for the cookbook's own household; any other household gets 403 with the detail "Nur der eigene Haushalt kann dieses Kochbuch ändern".
    - Before storing, `photo` is set to false for every recipe without `own_photo` (Review Focus 4).
  - `GET /api/kh/recipes/flags?slugs=a,b` → `dict[slug, {ownPhoto: bool}]`.
  - `PUT /api/kh/recipes/{slug}/flags` (body `{ownPhoto: bool}`) → the flags. Allowed only where `RecipeService.can_update([slug])` is true, else 403.
  - Unknown cookbook or recipe → 404.
- [ ] **Step 1: failing tests:**
  - defaults when nothing is stored;
  - PUT, then GET round trip;
  - the other household reads 200 and writes 403 (Review Focus 3);
  - a cookbook of another group → 404;
  - `photo: true` without the flag comes back `false`, and after setting the flag the same PUT keeps it `true`;
  - a title with 121 characters → 422;
  - servings 0 → 422;
  - flags PUT by a family member who may not edit → 403.
  
  Use `unique_user` and `household_member` from `tests/kh/conftest.py`. For the second household, look at how Mealie's cookbook tests build one.
- [ ] **Step 2–4:** fail, implement as a `BaseUserController` like `mealie/kh/notices/routes.py`, then green.
- [ ] **Step 5: commit** `"Book: print settings per cookbook and the own-photo flag (D43)"`

### Task 6: Print layout

**Files:**
- Create: `frontend/kh/app/components/KhPrintBook.vue`, `frontend/kh/app/assets/kh-print.css` (registered in `frontend/kh/nuxt.config.ts` `css`)

**Interfaces:**
- Consumes: `BookEntry` (Task 5), `khStepDisplay` with `oven` (Task 4).
- Produces: `<KhPrintBook :settings="KhBookSettings" :entries="BookEntry[]" :oven="Oven | null" :preview="boolean" />`.
  - The output is a sequence of `.kh-sheet` elements: a title page (if `titlePage`), a table of contents (if `toc`) with "Nr. n Titel", and one recipe per sheet start.
  - Each recipe sheet holds:
    - the title with "Nr. n" (only in a book with more than one entry);
    - servings and times;
    - the description (if on);
    - a photo (if `photo`);
    - two columns: ingredients (one third, scaled to `servings` the same way the recipe page scales them) and steps (via `khStepDisplay(...).html` in `SafeMarkdown`);
    - notes (if on).
  - In `@media print`: A4, margin 15 mm, `break-before: page` per recipe, `break-inside: avoid` on ingredient blocks and steps. Everything outside `.kh-print` is hidden, including Mealie's app bar, the bottom bar and the editor controls.
  - With `preview`, each `.kh-sheet` is shown on screen as a white A4 page (aspect 1 : 1.414, scaled to the column width, shadow), so the page breaks are visible before each recipe.
  - Theme: always black on white, independent of dark mode.
