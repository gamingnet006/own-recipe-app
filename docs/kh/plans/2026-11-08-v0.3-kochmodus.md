# Kochmodus v0.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mealie's cook mode gets a one-step view with big buttons, timers from the times in the step text, amounts next to ingredient names, and the last 30 recipes offline.

**Architecture:** Frontend only, in our Nuxt layer `frontend/kh/`. Pure functions in `kh/app/lib/` (time parsing, step display text), state in two composables (timers, cook position), two components (`KhCookStep`, `KhTimers`). Mealie files get small `KH:` hooks: the cook-mode switch in `RecipePage.vue`, the step text and time clicks in `RecipePageInstructions.vue`, the cache cleanup in `signOut()`. Offline caching goes into our layer's `nuxt.config.ts` (`pwa.workbox.runtimeCaching`), merged into Mealie's PWA config.

**Tech Stack:** Nuxt 4, Vue 3, Vuetify, `@vueuse/core` (`useSwipe`, `useWakeLock`, `useRouteQuery` already used), Workbox via `@vite-pwa/nuxt`, Vitest.

**Spec:** `docs/kh/specs/2026-11-08-kochmodus-design.md` (D42)

## Global Constraints

- No backend change, no migration, no new dependency (npm or Python). (Spec, Nicht-Ziele)
- Our code in `frontend/kh/`; every change in Mealie files is small and carries `KH: <reason>`. (CLAUDE.md, Fork-Regeln)
- Code, names and comments in English; every new file starts with 1–3 lines on its purpose; every function has a short description. (CLAUDE.md, Code-Regeln 5, 6)
- New texts only in `frontend/kh/lang/de-DE.json` and `en-US.json`, under `kh.cook.*` and `kh.timer.*`; never in Mealie's locale files.
- No hidden numbers: the limits (30 recipes, 150 images, 30 days, 2 minutes alarm, 12 steps for the segmented bar) are named constants in one place each.
- The stored step text never changes; additions appear only in the display. (D41, Spec E2)
- No sound file in the repo: the alarm is generated with Web Audio. (Spec E4)
- Times never scale with the factor. (Phase 3, Spec Nicht-Ziele)
- Frontend tests: the command from `.claude/CLAUDE.md` ("Frontend-Tests"); for a single file replace `pnpm test:ci` with `pnpm vitest run kh/app/__tests__/<file>`. The whole suite stays green before each commit.

## Review Focus

1. A step whose time sits inside Markdown (`**10 Min.**`, a list item, a link text) keeps its Markdown and its time stays clickable. → test in Task 2.
2. A food name that is part of another word ("Ei" in "Eigelb", "Salz" in "Salzwasser") gets no parenthesis. → test in Task 2.
3. A timer started, then the phone locked or the tab left for longer than the timer: on return it shows "fertig" at once and rings, it does not count on from where it stopped. → test in Task 3.
4. A recipe with 0 steps or 1 step in cook mode: no crash, "Fertig" on the only step, Zurück disabled. → test in Task 5.
5. Leaving cook mode or the recipe while a timer runs: the timer keeps running and stays visible on the recipe page and in other recipes, with a link back. → test in Task 3 (storage), manual check in Task 8.

## Spec correction (ruling)

The spec says a tap on a step in "Alle Schritte" jumps to that step. Mealie already uses that tap to tick a step off, and in the kitchen ticking off matters more. Ruling: the tap keeps ticking off as in Mealie. Next to Mealie's close button there is a button "Schritt für Schritt" that returns to the step view at the current step. The spec gets this change in Task 5. If this is wrong, the button simply becomes a tap handler.
