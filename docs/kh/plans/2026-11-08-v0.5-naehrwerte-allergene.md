# Nährwerte und Allergene v0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recipes show nutrition per serving from the BLS, the likely EU allergens with a warning for family members who cannot have them, and substitution hints with "save as variant".

**Architecture:**
- Backend `mealie/kh/nutrition/`:
  - the vendored BLS table, grams per ingredient line, the food → BLS mapping and the per-recipe calculation.
- Backend `mealie/kh/allergens/`:
  - the keyword rules, per-recipe corrections, the per-user profile, warnings, substitutions and variants.
- One additive migration `kh0005` with four tables.
- Frontend:
  - two blocks on the recipe page (`KhNutrition`, `KhAllergens`);
  - two pages under "Mehr";
  - a warning mark on recipe cards.

**Tech Stack:** FastAPI, SQLAlchemy and Alembic (`kh` branch), Pydantic; Python stdlib only for reading the BLS xlsx; Nuxt 4, Vue 3, Vuetify; pytest, Vitest.

**Spec:** `docs/kh/specs/2026-11-08-naehrwerte-allergene-design.md` (D44)

**Start:** from `main` after `v0.4`, on a new branch `kh/v0.5-naehrwerte` in its own worktree.

## Global Constraints

- **No new dependency** (Python or npm). The BLS xlsx is read with `zipfile` and `xml.etree` (spec N1).
- **Migrations only add tables;** `kh0005` revises `kh0004`. Rows of our tables are deleted in code when their recipe, food or user is deleted, like `delete_amounts` and the v0.4 book hooks (KH markers).
- **Code location:** our code goes in `mealie/kh/`, `frontend/kh/` and `tests/kh/`.
  - Mealie files change minimally and carry `KH: <reason>`.
  - Never edit `frontend/app/lib/api/types/` or Mealie's locale files.
  - TS API types are written by hand, as in `frontend/kh/app/lib/api/books.ts`.
- **Texts** go only in `frontend/kh/lang/de-DE.json` and `en-US.json`, under `kh.nutrition.*` and `kh.allergens.*`.
- **Named constants:**
  - `BLS_ZIP_URL` and `BLS_ZIP_SHA256` in `build_bls.py`;
  - `BLS_SEARCH_LIMIT = 20`;
  - `SALT_PER_SODIUM = 2.5`;
  - `DEFAULT_DENSITY = 1.0`.
- **Allergen keys** are exactly `gluten, crustaceans, eggs, fish, peanuts, soy, milk, nuts, celery, mustard, sesame, sulphites, lupin, molluscs`.
- **Wording:** always "wahrscheinlich" and "ohne Gewähr", never "frei von" (PLAN 9.8).
- **Test data:**
  - Self-written recipes only.
  - The tests use a small self-written `bls.csv` fixture, never the real file. The real `bls.csv` ships only for the app.
  - Tests never call real AI (D23).
- **Test commands:** as in `.claude/CLAUDE.md` (backend docker pytest, frontend docker vitest). Whole suites, `ruff format --check`, `ruff check mealie` and `pnpm lint --max-warnings=0` must be green before the branch is done.

## Review Focus

1. **A recipe whose lines have no food, no amount or unknown units** (e.g. "Salz und Pfeffer", "1 Bund Petersilie", "etwas Öl").
   - Expected: no crash and no zero-calorie lie.
   - The lines appear under "ohne", and "aus n von m Zutaten" is right.
   - → test in Task 4.
2. **A recipe without servings, or with yield text only.**
   - Expected: values "für das ganze Rezept", no division by zero.
   - → test in Task 4.
3. **Exceptions that must not trigger:** "Kokosmilch" (not milk), "Buchweizen" (not gluten), "Muskatnuss" (not nuts).
   - Hidden ones that must trigger: "Worcestersauce" (fish), "Brühe" (celery), "Pesto" (nuts, milk).
   - → the 20 cases in Task 5.
4. **Another household's recipe** (readable in the group):
   - Allergens and nutrition can be read.
   - Corrections return 403 unless `can_update`.
   - The warning names only members of the viewer's own household.
   - → test in Task 6.
5. **"Als Variante speichern" twice in a row.**
   - Expected: two copies with unique slugs. The original's ingredients, amounts links and allergen corrections are unchanged.
   - → test in Task 7.

### Task 1: BLS table and search

**Files:**
- Create: `mealie/kh/nutrition/__init__.py`, `mealie/kh/nutrition/build_bls.py`, `mealie/kh/nutrition/bls.py`, `mealie/kh/nutrition/data/bls.csv`
- Create: `tests/kh/nutrition/__init__.py`, `tests/kh/nutrition/test_kh_bls.py`, `tests/kh/nutrition/fixtures/bls.csv` (about 15 self-written rows)
- Modify: `docs/kh/THIRD_PARTY_NOTICES.md` (BLS 4.0 entry with the citation and licence from the spec)

**Interfaces:**
- Produces:
  - `BlsFood(code: str, name: str, kcal, fat, saturated, carbs, sugar, protein, fiber, salt: float | None)`, a frozen dataclass.
  - `load_bls(path: Path | None = None) -> dict[str, BlsFood]`. It is cached; the default path is `data/bls.csv` beside the module.
  - `search_bls(query: str, foods: dict[str, BlsFood], limit: int = BLS_SEARCH_LIMIT) -> list[BlsFood]`:
    - matches case-insensitively where the name contains every word of the query;
    - names that start with the first word come first, then shorter names.
  - `build_bls.py`:
    - `main()` downloads `BLS_ZIP_URL` with `urllib` (timeout 120 s), checks `BLS_ZIP_SHA256`, reads the xlsx sheet with `zipfile` and `xml.etree`, and writes the CSV;
    - `rows_from_xlsx(data: bytes) -> list[dict[str, str]]` and `to_csv_rows(rows) -> list[BlsFood]` are pure and tested;
    - salt = sodium (mg) × `SALT_PER_SODIUM` / 1000 g.
- **Step 0 (once, by the implementer):**
  - Run `build_bls.py` in the backend container to fetch the real ZIP. It comes from `https://www.blsdb.de/assets/uploads/BLS_4_0_2025_DE.zip` (about 14 MB, CC BY 4.0, approved in D44).
  - Find the nutrient column codes for kcal, fat, saturated fat, carbohydrates, sugar, protein, fibre and sodium. Write them as constants with a comment.
  - Pin the SHA-256 and commit the generated `bls.csv`. Do not commit the ZIP.
- [ ] **Step 1: failing tests:**
  - `rows_from_xlsx` on a tiny xlsx built in the test with `zipfile`: two rows, shared strings, one empty cell;
  - `to_csv_rows` computes salt from sodium;
  - `search_bls("mehl")` on the fixture lists "Weizenmehl Type 405" before "Roggenmehl Type 1150" when the fixture has both, finds nothing for "xyz", and caps at the limit;
  - `load_bls` reads the fixture with empty values as `None`;
  - the real `data/bls.csv` has more than 5000 rows and a non-empty `kcal` for most of them.
- [ ] **Step 2–4:** fail, implement, green. **Step 5: commit** `"Nutrition: BLS 4.0 table and search (D44)"`

### Task 2: Grams per ingredient line

**Files:**
- Create: `mealie/kh/nutrition/grams.py`, `mealie/kh/nutrition/data/weights.json`, `tests/kh/nutrition/test_kh_grams.py`

**Interfaces:**
- Consumes: Mealie's `RecipeIngredient` (quantity, unit name or abbreviation, food name) and `stem` from `mealie/kh/amounts/parse.py`.
- Produces:
  - `grams_of(ingredient: RecipeIngredient, piece_grams: float | None = None) -> float | None`.
  - It returns `None` when the line cannot be weighed (spec N3).
  - **Units:**
    - "g" and "kg" are direct;
    - "ml" and "l" use the food's density, or `DEFAULT_DENSITY`;
    - "EL", "TL", "Tasse" and "Becher" use their ml or g from `weights.json` times the density;
    - "Prise", "Msp." and unknown units give `None`.
  - **Pieces:** a line with no unit and a quantity counts as pieces. It uses `piece_grams`, else the food's piece weight from `weights.json` found by stem, else `None`.
  - Ranges use the lower end.
  - `weights.json` holds `{"units": {...}, "foods": {stem: {"density"?: float, "piece"?: float}}}` with about 60 foods (spec N3 examples).
- [ ] **Step 1: failing tests:**
  - "250 g Mehl" → 250;
  - "1 kg Kartoffeln" → 1000;
  - "500 ml Milch" → 515;
  - "2 EL Öl" → 27.6;
  - "3 Eier" → 165;
  - "1 Zwiebel" with `piece_grams=100` → 100;
  - "1 Prise Salz" → None;
  - "Salz" with no quantity → None;
  - "2–3 Äpfel" → 300;
  - "1 Dose Tomaten" → None.
- [ ] **Step 2–4:** fail, implement, green. **Step 5: commit** `"Nutrition: grams per ingredient line (D44)"`

  - `mealie/db/models/_all_models.py` (KH);

  - `mealie/services/backups_v2/alchemy_exporter.py` (`look_for_json` gets `allergens`, KH).
- Test: `tests/kh/nutrition/test_kh_mapping.py`, `tests/kh/allergens/test_kh_allergen_models.py`

**Interfaces:**
- **Models:**
  - `KhFoodNutrition(id, food_id → ingredient_foods.id unique, bls_code str|None, confirmed bool=False, piece_grams float|None)`;
  - `KhRecipeAllergen(id, recipe_id → recipes.id, allergen str, present bool; unique (recipe_id, allergen))`;
  - `KhUserAllergies(id, user_id → users.id unique, allergens JSON list)`;
  - `KhSubstitution(id, household_id → households.id, match str, replacement str, allergen str)`.
- **Mapping:** `suggest_code(food_name: str, foods: dict[str, BlsFood], aliases: dict[str, str]) -> str | None`. It looks up the alias by stem first, then takes the first `search_bls` hit whose name starts with the stem.
- **Mapping:** `food_mapping(session, group_id, food) -> FoodMappingOut`, with `FoodMappingOut(food_id, food_name, bls_code, bls_name, confirmed, suggested: bool, piece_grams, recipe_count)`.
- **Endpoints:**

  - `PUT /api/kh/nutrition/foods/{food_id}` takes the body `{blsCode: str|None, confirmed: bool, pieceGrams: float|None}` and returns `FoodMappingOut`. An unknown `blsCode` gives 422; a food of another group gives 404.
  - `GET /api/kh/nutrition/bls?q=` returns `[{code, name, kcal}]`, at most `BLS_SEARCH_LIMIT` entries.
- **`aliases.json`** maps about 60 common German food stems to real BLS codes found in Step 0 of Task 1. Examples: Mehl → Weizenmehl Type 405, Zucker → Zucker weiß, Butter, Milch 3,5 %, Ei, Sahne, Öl → Rapsöl, Zwiebel, Kartoffel.

  - deleting a recipe, food or user removes its rows;

  - the GET list puts unconfirmed foods first and counts recipes;
  - the PUT round trip works, an unknown code gives 422, and another group gives 404;
  - search caps at 20.
  - Use the fixture `bls.csv` through a monkeypatched path.

### Task 4: Nutrition per recipe

**Files:**
- Create: `mealie/kh/nutrition/calculate.py`
- Modify: `mealie/kh/nutrition/schemas.py`, `mealie/kh/nutrition/routes.py`
- Test: `tests/kh/nutrition/test_kh_calculate.py`

**Interfaces:**
- Consumes: `grams_of`, `food_mapping` and `suggest_code`, `load_bls`.
- Produces:
  - `NutritionOut(per: Literal["serving", "recipe"], servings: float | None, values: NutritionValues | None, counted: int, total: int, missing: list[str], estimated: bool, manual: bool)`.
  - `NutritionValues(kcal, fat, saturated, carbs, sugar, protein, fiber, salt: float | None)`, rounded as the spec N4 says.
  - `calculate(recipe: Recipe, mappings: dict[food_id, KhFoodNutrition], bls) -> NutritionOut`. It is pure.
  - **Rules:**
    - `manual` is true when any of Mealie's nutrition fields is filled; those values are then parsed as numbers where possible, and nothing is calculated.
    - A line counts when it has grams and a BLS entry (confirmed, or suggested; a suggestion sets `estimated`).
    - `missing` holds the display text of every line that did not count.
    - Section titles (lines with `title` only) are not lines.
    - A nutrient stays `None` only when no counted line has it.
  - `GET /api/kh/recipes/{slug}/nutrition` returns `NutritionOut` for any recipe of the group.
- [ ] **Step 1: failing tests:**
  - the recipe "250 g Mehl, 200 g Butter, 3 Eier, 150 g Zucker, 4 Portionen" against the fixture gives the hand-computed kcal per serving, `counted=4`, `estimated=True` until confirmed;
  - "Salz und Pfeffer", "1 Bund Petersilie" and "etwas Öl" are in `missing` with the right counts (Review Focus 1);
  - no servings gives `per="recipe"` (Review Focus 2);

  - a food mapped to "no entry" (`bls_code` None, confirmed) is missing, not suggested;

**Interfaces:**
- `Substitution(match: str, replacement: str, allergen: str, own: bool)`.
- `substitutions_for(recipe, hits, own_rules) -> list[LineSubstitution]`, with `LineSubstitution(line: str, allergen, replacement)`. Own rules come before the standard list; the first match per line and allergen wins.
- `GET /api/kh/substitutions` returns the household's own rules. `POST` adds one and `DELETE /api/kh/substitutions/{id}` removes one. All of them stay within the own household.
- The allergens GET from Task 6 now fills `substitutions`.
- **`POST /api/kh/recipes/{slug}/variant`** takes `{allergens: [key]}` and returns `{slug}`.
  - It duplicates the recipe through Mealie's `RecipeService.duplicate_one`, named "<Name> (ohne <Allergen, …>)".
  - On each affected line it sets the food to the replacement food, finding it by name in the group or creating it. Quantity and unit stay.
  - It returns 403 when the user cannot create recipes.
- [ ] **Step 1: failing tests:**
  - an own rule wins over the standard one;
  - the variant has the new name and replaced foods, and its allergens no longer contain the chosen key when the replacement is free of it;
